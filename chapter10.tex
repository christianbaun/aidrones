\coleng

For a UAV to operate autonomously, it must maintain a state estimate—a real-time calculation of its position, velocity, and orientation. To estimate the position and movement of the vehicle, the flight controller fuses data from several specialized sensors. Science sensor can generate noisy data, the Flight Controller takes data from multiple sensors and blends them to find "optimal estimate". Most common sensors used for position estimation are:

\colger

\coleng

\begin{itemize}
  \item \textsl{IMU (Inertial Measurement Unit)} - Tracks high-speed changes in acceleration and rotation in six directions to maintain basic flight attitude and stability.
  \item \textsl{GNSS (GPS)} - Finds the exact location on Earth using latitude and longitude with the help of satellites, helping devices know where they are for navigation.
  \item \textsl{Optical Flow} - Measures horizontal movement by tracking the ground surface movement beneath it, allowing the device to hold its position even when GNSS/GPS signals are unavailable (such as indoors).
  \item \textsl{Barometer} - Measures air pressure to estimate relative altitude. While less precise than LiDAR at low altitudes, it is essential for maintaining height at scales beyond the rangefinder's limit.
  \item \textsl{LiDAR (Rangefinder)} - Compared to the barometer, it provides better accuracy at low altitudes using laser pulses to measure the distance to the ground. It helps the UAV stay at the right height over the ground and land accurately.
\end{itemize}

With the accurate estimation of the drone’s state, the flight controller can move beyond manual flight into autonomous modes. In these modes, the system continuously monitors the drone’s position and automatically corrects any drift using sensor feedback:

\colger

TBD

\coleng

\begin{itemize}
  \item \textsl{Altitude Hold (Z-axis)} - The drone maintains a fixed height by using a rangefinder sensor at low altitude and a barometer at a higher altitude. This allows the operator to release the throttle while the drone keeps hovering at the same height. As this mode can be used with a barometer only and most modern flight controller comes with barometer preinstalled, Betflight, iNav and Arudpilot can activate this mode without requireing extra sensor.
  \item \textsl{Position Hold (X, Y axis)} - The drone keeps its horizontal position by using optical flow or GNSS (GPS) to detect movement. If wind or external forces push the drone, the flight controller corrects the displacement by moving it back to its original position.
  \item \textsl{Return to Home (RTH / RTL)} - This is one of the most common safety features in commercial drones. RTH is triggered automatically by failsafe mode, for example, if the battery is too low or the RC signal is lost, or manually by the user. When activated, the drone automatically flies back to its recorded home location using GNSS coordinates.
\end{itemize}

\renewcommand{\deutschertitel}{GPS-basierte Positionsbestimmung}
\renewcommand{\englischertitel}{GPS-Based Position Estimation}
\makroabschnitt
\label{GpsBasedPosition}

The main method used for high-level autonomous navigation in drones is Global Navigation Satellite Systems (GNSS). GNSS is a general term that includes several satellite systems such as Global Positioning System (GPS) from the United States, GLONASS from Russia, and Galileo from the European Union. These satellite systems provide the drone with a global reference and help the flight controller to estimate the vehicles exect position in terms of latitude, longitude, and altitude.

\colger

TBD

\coleng

Modern GNSS receivers (see Section~\ref{AbschnittReceiver}) used in drones and flight controllers such as ArduPilot, Betflight, iNav and px4 can use signals from multiple satellite navigation systems at the same time (i.e., GPS + Galileo or GPS + GLONASS + Galileo). Using several systems together increases the number of visible satellites, which improves positioning accuracy and makes navigation more reliable, especially in challenging environments.

\renewcommand{\deutschertitel}{Positionsbestimmung ohne GPS (Optischer Fluss und Entfernungsmesser)}
\renewcommand{\englischertitel}{GPS-Denied Position Estimation (Optical Flow and rangefinder sensor)}
\makroabschnitt
\label{GpsDeniedPositionEstimation}

In environments such as indoor spaces where Global Navigation Satellite Systems (GNSS) signals are not available, drones can use optical flow and rangefinder sensors for state estimation. These sensors provide local measurements that help the flight controller determine the drone’s motion and altitude without using satellite signals. Flight control firmware such as iNav, and ArduPilot can use this sensor data to support automated flight modes such as Position Hold and Altitude Hold.

\coleng

For high-speed sensors such as optical flow modules and GNSS receivers, a baud rate of 115200 is commonly used. However, it is recommended to verify the correct baud rate from the sensor manufacturer’s documentation. Optical flow sensors may use different communication protocols, and some devices—such as the MTF-01—support multiple protocols. \textbf{Copter 4.7 and later - MAVLink}: The protocol configuration is no longer tied directly to specific serial ports. Instead, it is controlled through the MAVn\_OPTIONS parameter. \renewcommand{\deutschertitel}{Konfigurationsschritt: C (EK3)}
\renewcommand{\englischertitel}{Configuration Step: C (EK3)}
\makrounterunterabschnitt

ArduPilot uses a state estimation algorithm called the Extended Kalman Filter (EKF) to determine the vehicle’s position, velocity, and orientation. The EKF combines measurements from multiple onboard sensors—such as gyroscopes, accelerometers, magnetometers, GPS receivers, and barometers—to generate a consistent estimate of the drone’s state. In recent versions of ArduCopter, including the stable version 4.6 and the development version 4.7, EKF3 serves as the primary estimator for navigation and position estimation. Because EKF3 can integrate data from additional sensors, it can also use optical flow sensors and rangefinders to assist position estimation. In GNSS-denied environments, these sensors can become the primary source of measurements required for estimating the drone’s motion relative to the ground.

\colger

TBD

\coleng

ArduPilot supports multiple sensor sources for the EKF3 estimator. A UAV can therefore be configured for indoor operation, where optical flow and rangefinder sensors act as the primary sources, or for outdoor use with GNSS. If both are available, a switch can be assigned to change between the sources during flight. By default, EK3 Source 1 is active and is typically configured to use GNSS-based measurements.

\colger

TBD

\coleng

It is recommended to assign an auxiliary switch to change the EKF3 source during flight. This switch can be used to switch the primary EK3 source between GPS and the Optical Flow with Rangefinder. To configure that way from mission planner software go to Config tab → Full Parameter List and search and set and save changes: (With \textbf{Summary step C})
\begin{enumerate} 
  \item Set \textbf{AHRS\_EKF\_TYPE} = 3 (default)
  \item Set \textbf{EK3\_SRC2\_POSXY} = 0 (None, as we do not want to use GPS)
  \item Set \textbf{EK3\_SRC2\_POSZ} = 2 (Rangefinder)
  \item Set \textbf{EK3\_SRC2\_VELXY} = 5 (Opticalflow)
  \item Set \textbf{EK3\_SRC2\_VELZ } = 0 (None - will disable GPS here) 
  \item Set \textbf{EK3\_SRC2\_YAW} = 1 (compass)
  \item set \textbf{RCn\_OPTION} = 90 (here n is the number of auxiliary channel in RC and 90 is for the EK3 source)
\end{enumerate}
